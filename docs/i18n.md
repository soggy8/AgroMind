# English and Macedonian

The whole site works in English and Macedonian: the interface, the sentences the backend writes (findings,
recommendations, assumptions, data notes, errors), dates, and the assistant, which answers in the language the
farmer chose. English is the default.

**Status (2026-11-15):** built. Translations were written by the developer, not a professional translator: have a
native speaker with farming vocabulary review `frontend/src/shared/i18n/mk/` and the backend `i18n_mk.py` files.

## How the farmer switches

- Top bar: the language-and-units button (🌐 + EN/МК) from 768 px; the EN | МК tabs on very wide screens; the
  menu on phones. The landing page has its own switch.
- `?lang=mk` or `?lang=en` in the address opens the site in that language.
- The choice is saved in the browser (`agromind.lang`). Switching reloads the page so every text, including what
  the backend already sent, comes back in the new language. The assistant conversation and unsaved results are
  not kept across the switch.

## Frontend: `frontend/src/shared/i18n/`

- Write English and wrap it: `t("Run simulation")`, `t("{n} fields to check", { n })`. The English text is the key.
  Plurals: `tn(n, "{n} field", "{n} fields")`. Missing translations show the English.
- Add the Macedonian to the area file in `mk/` (`app.ts`, `cropdoctor.ts`, `croptwin.ts`, `simulator.ts`,
  `shared.ts`, `extra.ts`).
- `npm run i18n:check` lists wrapped texts without Macedonian.
- Dates: `formatDate(date, options)`, not `toLocaleDateString` (browsers without Macedonian locale data fall back
  to US English). Numbers keep the point as decimal separator in both languages.
- Never translate values the code stores or compares (ids, `"Farmer-provided"`): translate where they are shown.

## Backend: `backend/app/shared/i18n.py`

- Modules keep writing English. A middleware translates every JSON response from `/api` when the request's
  `Accept-Language` is `mk` (the frontend always sends it).
- Each module has a catalogue `i18n_mk.py` (registered in `main.py`): exact phrases, and templates with `{name}`
  placeholders that match the module's f-strings. Captured values are translated too (rotation names, sub-phrases);
  `{day}`, `{year}` and `{num*}` match numbers only, `{rest*}` matches anything, other placeholders stay inside one
  sentence. Sentences and "; " lists are translated part by part.
- When you change a sentence in a module, change its template in that module's `i18n_mk.py`. Otherwise it shows
  in English (never broken). `tests/shared/test_i18n.py` fails when the demo farm's responses contain English
  sentences.
- Identifier fields (`id`, `crops`, `kind`, `status`, ...) and user data (farm and field names) are never translated
  (`SKIP_KEYS`). Citations and dataset names stay as published.
- The assistant translates its own streamed steps, facts and confirm cards (`modules/assistant/i18n_mk.py`) and
  tells the model to answer in Macedonian.
